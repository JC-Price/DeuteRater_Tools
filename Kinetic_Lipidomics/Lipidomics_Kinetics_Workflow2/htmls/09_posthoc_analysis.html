Post‑hoc Analysis & Statistics

Purpose of this module

This module bridges kinetic quantification and biological interpretation. It consolidates replicate‑level and model‑level metrics (abundance, turnover rate k, asymptote A, nL) into consistent comparisons between experimental and control groups, and generates volcano, conformity, and homeostasis plots grouped by ontology and higher‑order categories.

Design choice: Adducts are not collapsed—each Alignment ID is analyzed as its own observation to preserve polarity/adduct‑specific behavior.

How to run

  1. Select CSV files (one or more) containing your merged/wide metrics.
  2. Enter experiment–control pairs when prompted, e.g., (A2,A3),(A4,E3).
  3. When the GUI opens, use its tabs (Homeostasis, Volcano, Conformity, Settings) to choose plots, set filters, and pick normalization.
  4. Click Analyze. All outputs are written under Analysis/<versioned folder>/ next to your data.

You can import/export a YAML configuration in the Settings tab to reproduce identical runs later.

Normalization (Settings tab)

Choose one global method (applied consistently across experiments):

  • None (raw) — uses your input values as is.
  • mTIC — per‑polarity total‑ion current style scaling from in‑matrix abundances.
  • Standards (requires baseline) — robust log2 regression mapping of Experiment and Control to a specified baseline group, applied per polarity.
  • Quantile — per‑polarity quantile normalization (log2 → QN → linear).

For Standards normalization, provide a baseline group label (e.g., A3, which is used in Nielsen et al. 2026).

What the analysis computes

  • Abundance (replicate‑level):
    • Welch’s t‑test on log2 replicate abundances (Experiment vs Control).
    • BH FDR adjusted p‑values, fold‑change (FC) and -log10 p written to the table.
  • Turnover rate (k) and Asymptote (A) (model‑level):
    • Per‑row canonical Wald tests using covariance (and diagonal fallbacks if needed).
    • Individual tests for k and A plus a joint (A,k) omnibus Wald.
  • Flux:
    • Total flux metrics (Flux_Experiment = k_Experiment × Abundance_Experiment, likewise for Control).
    • P‑values via Fisher’s method combining the rate and abundance p‑values.

The analysis also attaches intuitive significance flags (FC thresholds + statistical cutoffs) for abundance and rate to support plotting and filtering.

Filters (applied inside tabs)

Each plot tab supports flexible row‑level filters. Supported forms:

  • Numeric comparisons in strings: "> 1.3", "<= 0.05", or even "> Other_Column" (column‑to‑column).
  • Ranges in dicts: {"min": 0, "max": 5}, with optional min_op/max_op to control strictness.
  • Text membership: "in:PE,PC", "not in:low score,no MS2".
  • Booleans and exact equality.

Token replacement: Where a filter key or column reference contains Experiment or Control, those tokens are replaced with the current IDs (e.g., abundance_median_log2_Experiment → abundance_median_log2_A2).

Note: Filters use token substitution; wildcard expansion of column names (e.g., *) is not performed.

Plot tabs & axes

Homeostasis

  • Panels per group (All, Ontology_*, HighOrder_*).
  • X = log2_abn_FC, Y = log2_rate_FC; background shows 0 axes and the y = −x reference line.
  • Optional outlines can reflect combined significance states.

Volcano

  • Metric‑specific x/y:
    • Abundance: X = log2_abn_FC, Y = -log10abnBH
    • Rate: X = log2_rate_FC, Y = -log10rate_P
    • Asymptote: X = asymptote_difference, Y = -log10_asymptote_p
    • Total Flux: X = log2_flux_FC, Y = -log10flux_p
  • Default thresholds: |log2FC| = 1 (vertical lines), −log10p = 1.3 (horizontal line).

Conformity (paired / one‑sample t‑tests)

  • Abundance (one‑sample on log2FC across paired rows): X = Control mean log2, Y = Experiment mean log2.
  • Rate, Asymptote, Flux (paired): X = Control metric, Y = Experiment metric.
  • Panels display an in‑figure summary (mean difference / mean log2FC, t, p, N) for the full and the filtered sets.

Grouping

Plots are generated for:

  • All
  • Each Ontology category present in your data (e.g., PC, PE, TG, CL, SM, …)
  • Available High‑order flags, if present (e.g., glycerolipids, Ethers, lysos, sphingolipids, Standards, neutral_lipids, …)

Ontology colors/markers are assigned consistently across panels for visual coherence.

Outputs

  • Plots (SVG) under Analysis/…/plot_outputs/<Group>/ for all enabled panels.
  • Paired‑t statistics summary: paired_ttest_statistics.csv.
  • Per‑comparison summary tables (if any group has p ≤ 0.05):
    • <Comparison>_Ontology.csv — rows are ontology groups with at least one significant metric.
    • <Comparison>_HighOrder_All.csv — rows are All and high‑order groups with at least one significant metric.
  • Filtered statistics (α = 0.05 and N ≥ 10): statistics_alpha0_05_minN10.csv.
  • Final merged dataframe for all experiments: final_dataframe.csv.
  • Datapoints for boxplots (cleaned): datapoints_for_boxplot.csv, plus rendered boxplot_*.png by metric and filtered/unfiltered state.

Tips

  • Use Settings → Normalization to set a single method; if choosing Standards, double‑check the baseline label.
  • Start with Volcano: Abundance to quickly triage large shifts, then use Conformity and Homeostasis to diagnose balance between abundance and rate.
  • Save your GUI configuration to YAML to rerun exactly the same analysis later.
Launch Post‑hoc Analysis

If Lipidomics_post_hoc_analysis1.2/main.cmd (or similar) exists in your working directory, the “Analyze Wide Dataframe” button will appear and execute it. On macOS/Linux, run the Python entry point directly.
