Building the Tidy Regression Matrix

Purpose of this step

The tidy regression matrix converts the wide lipidomics export into a long, analysis‑ready table for downstream modeling—covering abundance, turnover rate (k), asymptote (A), n‑value (nL), and their associated standard errors (SEs). This structure feeds genotype/diet/age/region regressions and nL component analyses.

What this tool does (exact behavior)

  1. Shows a pre‑filter dialog before selecting the wide CSV, letting you set:
    • Exponential‑decay R² cutoff (default shown in the dialog).
    • Maximum asymptote (A) threshold.
    • Maximum Abundance rate (K) threshold.
    • nL < nH enforcement toggle.
    Failing entries are set to NaN at the wide level so they are dropped during the melt.
  2. Strict header normalization of per‑sample columns to either <METRIC_TOKEN>_<sample_id> or <sample_id>_<METRIC_TOKEN>, from a fixed allow‑list of metric tokens (e.g., abundance_mean, n_value, Abundance rate, Abundance asymptote, and BA/SE variants). Only normalized matches are kept.
  3. Normalizes auxiliary columns required for filtering:
    • Abundance R2 columns standardized to Abundance R2_<sample> (accepting both metric_sample and sample_metric forms).
    • nH (hydrogen count) detected case‑insensitively and renamed to nH.
  4. Back‑fills Ontology from the first token of Alignment ID if Ontology is blank, and warns if the same Alignment ID maps to multiple ontologies.
  5. Applies wide‑level filters using your R²/A/K thresholds and optional nL < nH rule:
    • If a sample fails (R² below cutoff, or A/K above maxima), the script sets Abundance rate_<sample> and Abundance asymptote_<sample> to NaN for those rows.
    • When nL < nH is enabled and violated, n_value_<sample> is set to NaN.
  6. Wide → Long (melt) of metrics into columns: Alignment ID, optional Ontology, metric, sample_id, value.
  7. SE attachment: melts the available SE columns once and joins them back by (Alignment ID, metric, sample_id) to produce a tidy table with value and se per observation (supports n_value_SE, Abundance SE_K, Abundance SE_A, abundance_se, and BA SE variants).
  8. Interpretation dictionary: prompts for a Python‑dict/JSON mapping to decode each sample_id into regression variables (e.g., genotype, housing, sex), with support for map, regex, group, type, and order.
  9. Saves the tidy dataframe to CSV via a save‑as dialog (default filename: tidy_lipid_regression_with_ci.csv).

Inputs & outputs

  • Input: one wide lipidomics CSV that includes per‑sample metric columns and Alignment ID (and optionally Ontology).
  • Prompt: interpretation dictionary (Python dict or JSON) for deriving regression variables from sample_id.
  • Output: a tidy CSV with columns like Alignment ID, optional Ontology, metric, value, se, plus any decoded design‑matrix variables (e.g., genotype, sex, …).

Workflow overview (tidy creation)

  1. Normalize & filter (wide): canonicalize headers; enforce R²/A/K and optional nL < nH; drop sentinel values (e.g., −4).
  2. Melt metrics (abundance_mean, n_value, Abundance rate, Abundance asymptote, plus BA) into long rows.
  3. Add SEs by melting SE columns once and joining by ID/metric/sample to populate se.
  4. Interpret sample_id into variables using your dict (map and/or regex) with optional dtype and ordering.

Interpretation dictionary (examples)

Provide a Python dict or JSON that maps parts of sample_id to analysis variables.

Single‑factor example

{
  "genotype": {
    "map": {"A2": "APOE2", "A3": "APOE3", "A4": "APOE4"},
    "type": "category",
    "order": ["APOE3", "APOE2", "APOE4"]
  }
}

Multi‑factor example

{
  "genotype": {"E2": "APOE2", "E3": "APOE3", "E4": "APOE4"},
  "housing": {"2v3": "2v3", "4v3": "4v3"},
  "sex": {"YM": "Male", "YF": "Female"}
}

You can also use "regex" with "group" to extract tokens, and specify "type" / "order" for categorical encoding.

Notes & guardrails

  • Only columns whose names strictly match the supported metric tokens are considered during normalization; others are ignored.
  • SEs are used; if a needed SE column is absent, the se field is left blank for that observation. )
  • When Ontology is missing, it is inferred from the first term in Alignment ID only where blank, and a warning is shown if an Alignment ID maps to multiple ontologies.
