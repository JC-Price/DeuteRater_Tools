Lipidomic Kinetics — nL Component Deconvolution

Purpose

This module decomposes lipid-level n‑value measurements into component‑level contributions (fatty acids, headgroup, glycerol). It builds a design matrix from parsed lipid structures and uses Monte‑Carlo ridge regression to estimate per‑component nL, enabling comparisons across genotypes or conditions and optional overlay with literature values.

Required input (tidy CSV)

The script expects these columns (names are normalized on load):

  • Alignment ID (renamed internally to Sequence)
  • Ontology (lipid class)
  • metric (e.g., n_value, k, asyn)
  • value (numeric)
  • se (standard error; must be present and > 0)
  • genotype (renamed to group_name)

Rows with missing/≤0 se are dropped. Column renames and checks occur at start-up.

Interactive settings (GUI)

When launched, a small dialog gathers QC and display parameters:

  • SE ranges for k, Asyn, n (lower/upper). Lipid×group entries must fall within these per‑metric SE bounds to pass QC.
  • Component min % (informational): a rare threshold prompt is shown, but the model currently uses a fixed 5% prevalence filter (see below).
  • Monte‑Carlo iterations per genotype (default shown in the dialog).
  • Only show common components (intersection across groups in barplots).
  • Treat 0:0 as a component? (pads DG/TG when needed; toggles inclusion of the 0:0 token in modeling/plots).
  • Include ether species? (O-/P-; enables Ether* ontologies in parsing).
  • Literature component reference values — optional “FA = value” lines rendered as gray backdrop bars in component plots.

Parsing & eligibility

Lipid rows are kept only if they can be parsed into components:

  • Supported classes by default: PE, PC, PI, PS, PG, PA, DG, TG, LPE, LPC, LPA, LPG, LPI, LPS (plus their Ether* variants if enabled).
  • Species requirement: for main diacyl classes (PC/PE/PI/PS/PG/PA and DG), a species‑level ID must be present (e.g., contains a newline then “16:0/18:1”, etc.); otherwise the row is skipped.
  • FA extraction: recognizes tokens like 16:0, 18:1, pads to the expected count when needed (e.g., DG→3, lyso→2), and appends structural parts (Glycerol, Choline, etc.) per ontology.
  • By default ethers are excluded; check “Include ether species?” to keep them.

Quality control & data selection

  1. SE gates: for each lipid×group, take the max SE per metric and require k_SE ∈ [k_low, k_high], Asyn_SE ∈ [A_low, A_high] (ignored if all Asyn SE=0), and n_SE ∈ [n_low, n_high]. Non‑passing entries are excluded from modeling.
  2. nL filter: keeps only n_value > 10 before modeling.
  3. Rare components: components present in < 5% of lipids are dropped, and any lipids containing them are removed from the current genotype’s system. (The 5% threshold is fixed in the code.)

Model & estimation

For each genotype:

  • Build a 0/1/count design matrix A (lipids × components) from parsed components.
  • Use Monte‑Carlo sampling of observations via N(median, SE) (truncated if configured), then solve unconstrained ridge least‑squares for each draw (L2‑regularized).
  • Aggregate draws into per‑component Median, 2.5%, and 97.5% percentiles.
  • Optionally compute fit R² against the per‑lipid nL medians for diagnostics.

This implementation uses MC ridge (allows negative coefficients); it does not use non‑negative or bounded solvers.

Outputs

All outputs are written to a timestamped folder next to your input, for example: lipid_deconv_out_{basename}_{YYYYMMDD-HHMMSS}/.

  • Decision matrices: per‑genotype CSV containing A and matched rows (Ontology, Sequence, n_value, n_val_se).
  • Component summaries: per‑genotype CSV with Median, Lower, Upper per component; plus a combined summary table.
  • Bar plots (FA‑ordered): multi‑group bars with 95% CI whiskers; optional gray literature bars (full cluster width). Common‑component intersection can be enforced.
  • QC summaries & reasons: text/CSV files logging SE stats and parsing/eligibility drop counts.
  • Exported settings: all GUI inputs and literature entries saved for provenance.

Verification

To verify the correctness of the deconvolution logic (parsing → design matrix → Monte‑Carlo estimation), we replicated the workflow on peptides, where the true component stoichiometry (amino acids) is exactly known. Across the peptide benchmark, the method achieved an average deviation of ~0.5 per amino acid from ground‑truth composition—a strong check that the parsing, matrix assembly, and estimation steps recover known building blocks with high fidelity.

Because the lipid workflow reuses the same parsing, eligibility, design‑matrix construction, and Monte‑Carlo regression machinery documented above, the peptide results provide a practical, independent validation of this implementation end‑to‑end.
